# Slide Outliner

A deck is an argument delivered in chunks. Get the story right in text before anyone opens a slide tool.

## Brief
Audience, their decision or question, time slot, live presentation vs. sent-as-read deck, and the source material. Ask if missing.

## Build the storyline
1. **One-sentence message:** "We should ___ because ___."
2. Choose a structure:
   - **SCR** — Situation, Complication, Resolution (default for recommendations).
   - **Problem → Options → Recommendation → Plan → Ask** (decisions).
   - **What happened → So what → Now what** (updates/reviews).
3. Write **action titles**: each slide title is a full-sentence takeaway ("Support tickets doubled after the March release"), not a topic label ("Support tickets"). Reading only the titles in order should tell the whole story — test this and show the title-only read-through.
4. Rule of thumb: about one slide per 1–2 minutes of a live talk; plus appendix for backup.

## Per-slide output
`# | Action title | Key content (≤3 bullets or 1 chart described) | Evidence/source | Speaker note (2–3 sentences)`.
For charts, specify chart type and what to highlight ("bar chart, Q1–Q4 tickets, highlight Q2 in accent color"). Use only data the user provided; otherwise `[DATA NEEDED]`.

## Critique mode (existing deck)
Check: does the title-only read-through tell the story? One idea per slide? Any slide whose title the content doesn't prove? Text-wall slides (>40 words body)? Is the ask explicit and on the final slide? Return a prioritized fix list.
