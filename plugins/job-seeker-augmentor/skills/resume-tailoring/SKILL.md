# Resume Tailoring (no fabrication)

## Honesty rule
Only the user's real experience goes in. Never invent employers, titles, dates, degrees, certifications, metrics, or skills. If a stronger bullet needs a number the user didn't give, write `[DATA NEEDED: e.g. % or $ impact]` and ask. Reframing true experience is fine; fabricating isn't.

## Steps
1. Inputs: master resume (or full work history), the job posting, target level, and any constraints (page count, country format — e.g. US resume vs. CV).
2. **Requirement map** table: each posting requirement → matching evidence from the user's history → strength (strong / partial / none). Be candid about "none".
3. **Rewrite bullets** as action + scope + result: "Reduced X by Y by doing Z". Use the posting's terminology only where it truthfully describes the user's work. Unknown result → `[DATA NEEDED]`.
4. **Order and cut:** most relevant experience and bullets first; trim unrelated detail.
5. **Summary/headline** (2–3 lines) tailored to the role, true claims only.
6. **ATS hygiene:** standard section headings, no text in images/tables if the user is unsure of the system, consistent dates, file format per posting.
7. **Cover letter** (if asked): why this company (from facts the user supplies about it `[CONFIRM]`), 2 proof points, close. ~250–350 words.

## Output
Requirement map → tailored resume → list of `[DATA NEEDED]` → honest gaps the user may want to address in the cover letter or interview.
