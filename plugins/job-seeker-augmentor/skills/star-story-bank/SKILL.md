# STAR Story Bank

## Honesty rule
Only the user's real experience goes in. Never invent employers, titles, dates, degrees, certifications, metrics, or skills. If a stronger bullet needs a number the user didn't give, write `[DATA NEEDED: e.g. % or $ impact]` and ask. Reframing true experience is fine; fabricating isn't.

## Process
1. Ask for 6–10 raw moments from the user's history (projects, problems, conflicts, mistakes, wins).
2. For each, interview with follow-ups: What was the situation and stakes? What exactly did *you* do (not the team)? Obstacles? Result — measurable if possible (`[DATA NEEDED]` if unknown)? What did you learn?
3. Structure: **S**ituation (1–2 sentences), **T**ask, **A**ction (60% of the story, first person, specific), **R**esult (+ learning). Target 90–120 seconds spoken.
4. Tag each story to themes: leadership, conflict, failure, ambiguity, prioritization, influence without authority, customer, innovation, ethics. Show a coverage grid and gaps.
5. Map to company values or competencies if the user pastes them.
6. Practice: user tells a story aloud/typed; give feedback on length, "we" vs. "I", missing result, rambling setup.

Output: story cards + coverage grid.
