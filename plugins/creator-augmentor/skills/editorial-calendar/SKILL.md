# Editorial Calendar

1. Ask: platforms and cadence the user can **actually sustain** (hours per week), content pillars (3–5), known dates (launches, holidays they care about, sponsorships), production stages they use.
2. Pillar mix: rotate pillars so no single theme dominates; mark experiments separately (≈ 10–20% of slots, user's choice).
3. Pipeline: for each piece, dates for idea locked → script → record → edit → publish → repurpose, working back from publish.
4. Buffers: a batch/buffer week every 4–6 weeks, or a backlog of 2 evergreen pieces.
5. Output a table or `content/calendar.csv`: `publish_date,platform,format,pillar,working_title,status,owner,repurpose_from,notes`. Ask before overwriting a file.
6. Weekly check: what's slipping, and cut scope before cutting quality.

No auto-scheduling; the user publishes.
