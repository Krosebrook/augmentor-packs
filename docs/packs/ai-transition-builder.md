# AI Transition Builder (`ai-transition-builder`)

> Coach for people with some technical background moving into building with AI: prompt engineering, agentic workflow design, LLM API integration, RAG basics, evals, shipping a prototype, a personal learning roadmap, reviewing AI-generated code, and LLM app security. Teaches by having you build.

Version 1.4.0 · License MIT · Source: [`plugins/ai-transition-builder`](../../plugins/ai-transition-builder) · Pack README: [README](../../plugins/ai-transition-builder/README.md)

**Level: Advanced** ([what levels mean](../index.md#levels)). Assumes some coding background: APIs, RAG, evals, and reviewing code.

## Who it's for

People with some technical background (developers, analysts, IT, data folks) moving into building with AI. It teaches by having you build.

## Install

```
/plugin marketplace add Krosebrook/augmentor-packs
/plugin install ai-transition-builder@augmentor-packs
```

See [installation](../installation.md) for local-path installs and troubleshooting.

## Skills

Skills load automatically when your request matches their description. You can also run one directly as `/ai-transition-builder:<skill>`.

### `agentic-workflow-design`

**When to use:** Use when the user wants to design an AI agent, multi-step LLM workflow, tool-using assistant, or automation with LLM calls — or is deciding whether they need an "agent" at all. Picks the simplest workable pattern, defines tools, control flow, guardrails, and failure handling before any code.

**Example prompt:** “I want an agent that reads support tickets and drafts replies. Do I even need an agent?”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/agentic-workflow-design/SKILL.md)

### `ai-app-security`

**When to use:** Use when the user is building or reviewing an application that uses LLMs and needs to think about security, safety, or abuse — prompt injection, data leakage, tool permissions, untrusted documents, cost abuse, content risks. Runs a structured threat model referencing the OWASP Top 10 for LLM Applications.

**Example prompt:** “Threat-model my chat-with-PDFs app. Users can upload any document.”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/ai-app-security/SKILL.md)

### `ai-code-review`

**When to use:** Use when the user has code generated by an AI assistant (or copied from one) and wants to understand it, check it, or decide whether to trust it before merging or running it. Reviews for correctness, hallucinated APIs, security, and maintainability — and makes sure the user can explain the code.

**Example prompt:** “Copilot wrote this function. Review it and make sure I actually understand it before I merge.”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/ai-code-review/SKILL.md)

### `ai-evals`

**When to use:** Use when the user needs to test or measure LLM output quality — building an eval set, writing graders, LLM-as-judge, regression testing prompts or models, or deciding whether a change made things better. Trigger on "how do I know if this prompt is better", "test my AI feature", "evals".

**Example prompt:** “How do I know if my new summarization prompt is better than the old one?”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/ai-evals/SKILL.md)

### `learning-roadmap`

**When to use:** Use when the user asks what to learn to move into AI engineering or building with AI, how to structure their learning, which skills matter, or how to build a portfolio. Builds a project-driven roadmap from the user's actual background, time budget, and goal.

**Example prompt:** “I'm a backend dev with 5 hrs/week. Build me a roadmap into AI engineering.”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/learning-roadmap/SKILL.md)

### `llm-api-builder`

**When to use:** Use when the user is writing code that calls an LLM API or SDK — chat/messages calls, streaming, tool/function calling, structured JSON output, retries, cost and token management. Guides them to build it themselves with production habits, and checks current provider docs instead of trusting memory for model names, parameters, or prices.

**Example prompt:** “Help me add streaming and tool calling to my LLM API calls, with retries.”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/llm-api-builder/SKILL.md)

### `prompt-engineering`

**When to use:** Use when the user is writing, debugging, or improving a prompt or system prompt for an LLM feature, or asks why a model output is inconsistent. Reviews prompts against a concrete checklist, proposes targeted changes, and insists on testing them against examples rather than vibes.

**Example prompt:** “My classifier prompt gives inconsistent labels. Here's the system prompt — what's wrong?”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/prompt-engineering/SKILL.md)

### `prototype-shipping-coach`

**When to use:** Use when the user wants to build and ship an AI prototype or side project, is stuck in tutorials or planning, or keeps expanding scope. Coaches scoping to a one-week slice, a build plan, daily check-ins, and a demo — the user builds it.

**Example prompt:** “I keep adding features to my side project. Help me scope a one-week slice and ship it.”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/prototype-shipping-coach/SKILL.md)

### `rag-basics`

**When to use:** Use when the user wants an LLM to answer questions over their own documents or data — retrieval-augmented generation, embeddings, vector databases, chunking, "chat with my docs", or when a RAG system gives wrong or unsupported answers. Teaches a baseline-first build and how to diagnose retrieval vs. generation failures.

**Example prompt:** “My chat-with-docs bot gives confident wrong answers. Is it retrieval or generation?”

Source: [SKILL.md](../../plugins/ai-transition-builder/skills/rag-basics/SKILL.md)

## Commands

### `/ai-transition-builder:eval-plan`

**What it does:** Create an evaluation plan, starter test cases, and graders for an LLM feature.

**Arguments:** `[describe the feature or path to its prompt/code]`

**Example:** `/ai-transition-builder:eval-plan "support-ticket classifier, prompts/classify.md"`

Source: [eval-plan.md](../../plugins/ai-transition-builder/commands/eval-plan.md)

### `/ai-transition-builder:next-step`

**What it does:** Get your single next learning or building step based on your roadmap and what you've done.

**Arguments:** `[what you've done recently / where you're stuck]`

**Example:** `/ai-transition-builder:next-step "finished a RAG tutorial, stuck on evals"`

Source: [next-step.md](../../plugins/ai-transition-builder/commands/next-step.md)

### `/ai-transition-builder:prompt-review`

**What it does:** Review a prompt or system prompt against a concrete checklist and get a revised version plus test inputs.

**Arguments:** `[path to prompt file or paste prompt]`

**Example:** `/ai-transition-builder:prompt-review prompts/system.md`

Source: [prompt-review.md](../../plugins/ai-transition-builder/commands/prompt-review.md)

### `/ai-transition-builder:ship-checklist`

**What it does:** Pre-ship checklist for an AI prototype — scope, evals, errors, cost, security, demo.

**Arguments:** `[path to project or short description]`

**Example:** `/ai-transition-builder:ship-checklist ./my-prototype`

Source: [ship-checklist.md](../../plugins/ai-transition-builder/commands/ship-checklist.md)

### `/ai-transition-builder:threat-model`

**What it does:** Threat-model an LLM app or agent against the OWASP Top 10 for LLM Applications.

**Arguments:** `[path to project or architecture description]`

**Example:** `/ai-transition-builder:threat-model ./my-agent-app`

Source: [threat-model.md](../../plugins/ai-transition-builder/commands/threat-model.md)

## Agents

Claude can delegate to these subagents on its own, or you can call one with `@agent-ai-transition-builder:<agent>`.

### `ai-code-reviewer`

**When to use:** Reviews AI-generated or AI-assisted code changes for hallucinated/nonexistent APIs and packages, correctness bugs, security issues, and weak tests, then produces comprehension questions so the author understands what they're merging. Use after an AI assistant writes or modifies code, or when the user asks to review a diff.

**Tools:** Read, Grep, Glob, Bash · **Model:** inherit

**Example prompt:** “@agent-ai-transition-builder:ai-code-reviewer review my last commit's diff.”

Source: [ai-code-reviewer.md](../../plugins/ai-transition-builder/agents/ai-code-reviewer.md)

### `llm-app-security-auditor`

**When to use:** Read-only security audit of a codebase that uses LLMs or agents — traces untrusted input into prompts, tool permissions and side effects, output handling, secrets, and cost controls, mapped to the OWASP Top 10 for LLM Applications (2025). Use for a deep security pass before shipping an AI feature.

**Tools:** Read, Grep, Glob · **Model:** inherit

**Example prompt:** “@agent-ai-transition-builder:llm-app-security-auditor audit this repo before launch.”

Source: [llm-app-security-auditor.md](../../plugins/ai-transition-builder/agents/llm-app-security-auditor.md)

## Guardrails

- You build it. The coach scopes, reviews, and asks questions instead of writing the whole project for you.
- Checks current provider docs instead of trusting memory for model names, parameters, or prices.
- AI-generated code isn't merged until you can explain it; the reviewer produces comprehension questions.
- Prompt and model changes are tested against examples and evals, not vibes.
- Security auditing is read-only (the auditor agent has Read/Grep/Glob tools only) and references the OWASP Top 10 for LLM Applications.

See [guardrails](../guardrails.md) for the principles behind these rules.

## Sample workflows

**From zero to a shipped prototype.** `learning-roadmap` → `prototype-shipping-coach` to scope a one-week slice → `llm-api-builder` while building → `/ai-transition-builder:eval-plan` → `/ai-transition-builder:threat-model` → `/ai-transition-builder:ship-checklist`.

**Reviewing AI-written code.** After an assistant edits code, run `@agent-ai-transition-builder:ai-code-reviewer` on the diff and answer its comprehension questions before merging.

**Fixing a flaky prompt.** `/ai-transition-builder:prompt-review` → apply the targeted changes → re-run your eval set (`ai-evals`).
